# Fightergame

An original 2D fighting game: three fighters, frame-data driven combat, motion-input specials, a CPU
opponent with four difficulty levels. Built in **Godot 4.7** for **Android** and **Steam (Windows/Linux)**,
with an art pipeline that turns **Google Flow** text-to-image generations into game sprites and stages.

| Fighter | Style | Specials |
|---|---|---|
| **Ryokan** — The Balanced Warrior | all-rounder | Fireball (QCF+P), Rising Uppercut (DP+P), Hurricane Kick (QCB+K) |
| **Shadow** — The Silent Assassin | fast, double jump, air dash | Shadow Port (QCF+P), Shadow Grab (HCB+K), Kunai Toss (QCB+P) |
| **Titan** — The Unstoppable Force | slow, armored | Ground Pound ([charge ↓] ↑+K), Armor Rush ([charge ←] →+P), Mega Slam (HCF+P) |

> **New to Godot?** Start with [docs/GODOT_FOR_PYTHON_DEVS.md](docs/GODOT_FOR_PYTHON_DEVS.md). It maps the
> pygame prototype onto Godot and walks you through your first session.

## Repository layout

```
godot/                     the game (open this folder in Godot 4.7)
  data/characters/*.json   SOURCE OF TRUTH for stats, moves and frame data
  scripts/sim/             pure simulation: no nodes, no rendering, deterministic, 1 step = 1 frame @60Hz
  scripts/view/            presentation: menus, HUD, input (keyboard/gamepad/touch), sprites, effects
  assets/sprites/<char>/   generated by the sprite pipeline (manifest.json + PNGs)
  assets/stages/<stage>/   generated by the sprite pipeline
  tests/                   headless GDScript tests (run_tests.gd runner)
  export_presets.cfg       Android / Linux / Windows presets
tools/sprite_pipeline/     Google Flow -> Godot art pipeline (Python)
tools/export_characters.py one-shot: prototype/character_defs.py -> godot/data/characters/*.json
prototype/                 original pygame prototype (bug-fixed, kept as a reference + pytest suite)
scripts/run_godot_tests.sh headless test runner
```

## Running

```bash
godot --path godot                      # play (or open godot/project.godot in the editor and press F5)
godot --path godot -- --touch           # desktop with the on-screen touch controls (mouse = finger)
godot --path godot -- --autoplay        # CPU vs CPU demo; add --mode=0 for VS CPU, --seed=N to fix the AI
```

**Controls** (player 1): arrows move/jump/crouch · **A** punch · **S** kick · **D** special · **Shift** heavy ·
**Esc** pause · **F1** hitbox/frame-data overlay. Player 2: numpad 4/6/8/5 + 1/2/3, 0 = heavy.
Gamepads: d-pad/left stick, X punch, A kick, B special, Y/RB heavy, Start pause. On phones: floating stick on the
left half of the screen, P/K/S/H buttons on the right, pause button top centre, Android back = pause.

| Input | Result |
|---|---|
| back (away from opponent) | walk back + standing guard |
| down + back | crouching guard (plain down does **not** guard) |
| forward + heavy + punch | overhead (must be blocked standing) |
| down + button | low (must be blocked crouching) |
| heavy + forward/back (no button) | dash / back dash (back dash has invincible frames) |
| up in the air (Shadow) | double jump; heavy in the air = air dash |

Matches are best of 3, 99-second rounds; on time-out the fighter with more health wins the round.

## Tests

```bash
scripts/run_godot_tests.sh                                       # 49 simulation tests (Godot, headless)
scripts/run_godot_tests.sh test_blocking                         # filter by file / test name
cd prototype && conda run -n pygame python -m pytest -q          # 43 prototype tests
conda run -n pygame python -m pytest -q tools/sprite_pipeline/tests   # 7 pipeline tests
```

The Godot suite is a port of the prototype's pytest suite (same scenarios, same expectations) plus tests for
projectiles, armor, invincibility, teleport, the round/timer flow, and CPU-vs-CPU determinism for every matchup.

## Art pipeline (Google Flow → sprites)

Google Flow has no public API, so generation is done by hand in the browser and everything else is scripted.
Use the `pygame` conda env (it has Pillow + numpy).

```bash
conda run -n pygame python tools/sprite_pipeline/pipeline.py prompts   # -> tools/sprite_pipeline/prompts/PROMPTS.md
conda run -n pygame python tools/sprite_pipeline/pipeline.py status    # what's generated / missing
conda run -n pygame python tools/sprite_pipeline/pipeline.py process   # flow_raw/ -> godot/assets/ (+ Godot re-import)
```

1. `prompts` writes one copy-paste prompt per image with the exact file name to save it as. All prompts share a
   style preamble and ask for a **flat #00FF00 green background**, side view, facing right.
2. For each character, generate the **reference sheet** first and attach it as an *ingredient*/reference
   image to every other prompt of that character. Without this, the character's design drifts between images.
3. Save downloads to `tools/sprite_pipeline/flow_raw/<char>/<name>.png` (stages: `flow_raw/stages/<id>.png`).
   This folder is git-ignored. Animation loops can be one image with frames side by side: `<anim>_strip.png`.
4. `process` keys out the background (auto-detecting the actual green, despilling only the edges), crops,
   scales every frame to the fighter's in-game height (crouch 70 %, knockdown 40 %…), puts the feet on a fixed
   anchor, centres on the body (not on an outstretched limb), writes the PNGs + `manifest.json`, and re-imports.
   Stages are cover-fitted to 1200×700 with their floor line on the game's ground line.

### Walkthrough: your first fighter's art (about 1 hour for tier 1)

1. **Get the list**: `conda run -n pygame python tools/sprite_pipeline/pipeline.py prompts`, then open
   `tools/sprite_pipeline/prompts/PROMPTS.md` (VS Code's Markdown preview makes the checkboxes easy to follow).
2. **Make the folder**: `mkdir -p tools/sprite_pipeline/flow_raw/ryokan`
3. **Reference sheet**: in Google Flow, paste Ryokan's *Reference sheet* prompt. Generate, pick the variant you
   like most, download it, and save it as `flow_raw/ryokan/reference.png`. This image defines what Ryokan looks like.
4. **Poses**: for each tier 1 prompt, attach `reference.png` as an ingredient/reference image, paste the prompt, and
   generate. Pick the variant that matches the reference best and save it with the exact name from the checklist
   (e.g. `idle_1.png` … `idle_4.png`, `punch_startup.png`, `punch_active.png`, `punch_recovery.png`).
   - Re-roll if the background isn't flat green, the figure is cut off, or it faces left.
   - Any image size or aspect ratio is fine; the pipeline normalises everything.
5. **Check progress**: `pipeline.py status` lists what's still missing.
6. **Import**: `pipeline.py process` (or `process --char ryokan` while iterating). It writes
   `godot/assets/sprites/ryokan/` and tells Godot to import the new images.
7. **Look at it**: `godot --path godot`. Ryokan's select card and fight now use your art. Press **F1** in a fight
   to check that the sprite lines up with the blue hurtboxes. If a frame looks too big or small, the pose's
   `height` in `art_spec.toml` is the knob to turn. Re-run `process` after changing it.
8. **Stages**: generate from the *Stages* prompts, save as `flow_raw/stages/<id>.png`, run `process`, then pick the
   stage on the select screen. If the floor sits too high or low, change that stage's `floor_y` in `art_spec.toml`.
9. **Commit** the results in `godot/assets/` (the raw `flow_raw/` folder stays out of git).

To change the art style for everyone, edit `[style] preamble` in `art_spec.toml`, re-run `prompts`, and regenerate.

Start with **tier 1** (22 images per fighter: idle, walk, crouch, jump, hit, generic punch and kick in three
phases). Everything missing falls back: a move without its own art uses the generic punch/kick art,
a missing pose uses idle, and a fighter with no art at all uses the procedural placeholder. Attack art is timed by
frame data: the `startup`, `active` and `recovery` images play during those phases of the move.

Look and poses live in `tools/sprite_pipeline/art_spec.toml`. Attack animations are derived from the move list in
`godot/data/characters/*.json`, so new moves get prompts automatically.

## Exporting

1. Install export templates once: Godot editor → *Editor → Manage Export Templates → Download* (4.7.2).
2. **Android**: install the Android SDK + a JDK, set their paths in *Editor Settings → Export → Android*. Change
   `package/unique_name` in `godot/export_presets.cfg` (currently `com.example.fightergame`) before publishing.
   Provide release keystore credentials via Godot's env vars
   (`GODOT_ANDROID_KEYSTORE_RELEASE_PATH/_USER/_PASSWORD`), never in the repo.
   `godot --headless --path godot --export-release Android ../build/android/fightergame.apk`
3. **Steam (Windows/Linux)**: `godot --headless --path godot --export-release Linux ../build/linux/fightergame.x86_64`
   (or `Windows`). The desktop presets set the `steam` feature tag for later Steamworks integration (e.g. GodotSteam).

## Version 4: Skeleton2D route and the modern-Pakistan roster

Branch `version4-godot-animation` moves the art from frame-by-frame sprites to **cutout animation**: each fighter
is one painted character cut into parts and placed on a shared Godot `Skeleton2D`, so the animation comes from the rig,
timed by frame data, not from ~80 generated frames per fighter.

The roster (`tools/rig_art/roster.toml`) is 16 fighters: for each of Punjab, Sindh, Khyber Pakhtunkhwa and
Balochistan, one urban man, one urban woman, one rural man and one rural woman. Three of them take over the existing
frame data first: **Ali Changezi** (Quetta karateka) ← `ryokan`, **Hamza** (Lahore rooftop runner) ← `shadow`,
**Bashir Pehlwan** (Gujranwala kushti wrestler) ← `titan`. The others are concepts with a fighting style; moves come later.

```bash
python tools/rig_art/rig_prompts.py prompts   # -> tools/rig_art/prompts/RIG_PROMPTS.md (3 images per fighter)
python tools/rig_art/rig_prompts.py status
python -m pytest -q tools/rig_art/tests
```

Per fighter: `reference` (the approved look) first, then `parts` (the sheet that actually gets cut) and `portrait`
with the reference attached. Save into `tools/rig_art/rig_raw/<id>/` as .png or .jpg (git-ignored). Far-side limbs are
darkened copies of the near ones, so they aren't generated. Each fighter has its own chroma key
(magenta by default, green for outfits heavy in pinks and reds). Fighters are tagged `easy`/`medium`/`hard` by how
much loose cloth they have; rig the easy ones first (Bashir, Ali, Shahzaib, Mureed, Palwasha).

Next steps are written up in [docs/RIG_PLAN.md](docs/RIG_PLAN.md): cut the parts sheet (`cut.py`), label the pieces,
click the joint pivots (`pivots.py`), build `rig.json` (`build_rig.py`), then the `FighterRig` view node and the pose
library timed by frame data.
